# 12｜后续升级方案与路线图

路线图根据用户验证结果推进，不以功能数量为完成标准。阶段时间是个人开发计划区间，不是工期承诺；平台审核和客户反馈可能改变先后顺序。

## 阶段 0：当前 MVP，单用户闭环

交付：本地工作台、文件和文本采集、目录监控、AI 整理、知识沉淀/版本/关键词检索、多平台内容草稿、人工审核/发布记录、线索管理、备份与测试。

门槛：核心流程端到端通过；至少收集 5–10 位真实用户反馈；出现明确付费意愿。

## 阶段 1：产品质量和知识增强

1. 账户和个人空间（早期可继续本地版）。
2. 数据导出、删除、附件下载和清理。
3. 知识详情、版本差异、来源定位。
4. 去重：文件哈希、规范化文本指纹、相似候选。
5. 冲突检测：价格、政策、客户信息等新旧差异提醒，不自动覆盖。
6. 中文检索增强：PostgreSQL FTS/BM25 + pgvector 混合检索。
7. Embedding 配置、索引重建和检索评测集。
8. 文档解析异步化；OCR 插件化并作为可选模块。
9. 桌面端托盘、快捷键和用户主动剪藏。

## 阶段 2：SaaS 化

### 后端

Java 21 + Spring Boot 3 模块化单体；PostgreSQL + pgvector；Redis 用于缓存和任务协调；真实需要时再加队列；S3/MinIO 对象存储；Flyway 迁移；OAuth 登录、租户隔离、RBAC、审计；订阅、用量和成本统计。

### 前端

Vue 3 Composition API + TypeScript + Vite；Pinia；Vue Router；Element Plus 基础组件，保留中性色视觉方向。

### AI

保留 Python AI 服务；复杂工作流使用 LangGraph；Java 后端负责业务状态和权限，AI 服务不能直接越权改业务表。

迁移策略：先稳定 API 契约，再迁移数据；不要一次性推翻重写。

## 阶段 3：官方平台连接器

逐个平台完成开发者资质、应用审核、OAuth 回调、Token 加密与刷新、能力矩阵、配额监控、内容发布任务、状态回查、幂等、失败重试和操作审计。按授权难度和客户价值排优先级。不能把某平台的电商开放能力推断成普通创作者笔记发布权限。所有接口应上线前再次核实官方文档。

## 阶段 4：Agent 工作流

优先实现每日信息简报、新资料整理建议、知识更新冲突提醒、每周选题、基于知识生成内容矩阵、审核提醒和线索回填。Agent 必须有状态、步骤、来源、费用和人工确认节点，限制工具权限、循环步数和预算。

## 阶段 5：企业/代运营版

多租户、组织成员、角色和项目空间；客户/品牌独立知识库和风格；客户审核门户；多渠道账号授权和日历；线索归因、跟进和报表；团队额度池和套餐；企业数据保留、审计及私有部署。

## 里程碑与 Go/No-Go

| 里程碑 | 验证内容 | 继续投资条件 |
|---|---|---|
| M1 核心闭环 | 导入→知识→内容 | 用户认为明显节省时间 |
| M2 高频使用 | 每周使用核心流程 2–3 次 | 可观察的复访和留存 |
| M3 付费 | 真实付费 | 有可复用获客渠道 |
| M4 SaaS 化 | 多用户隔离、权限、审计 | 单位经济模型有正向趋势 |
| M5 平台自动化 | 官方授权和稳定性 | 平台成本与用户收益匹配 |

## 近期不建议投入

原生 iOS/Android、自研大模型、Kubernetes、过早微服务、未经许可的自动登录/批量评论/私信、未验证付费前建设复杂企业计费和私有化体系。
