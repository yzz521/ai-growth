# 04｜数据库设计（MVP）

当前 SQLite；ID 为 UUID；时间为 ISO-8601 UTC 字符串。

## ER 关系

```text
inbox_items 1 ── 0..1 knowledge_entries ── 1..N knowledge_versions
knowledge_entries N ── N content_drafts（MVP 通过 JSON ID 列表）
content_drafts 1 ── N publish_records
content_drafts 1 ── N leads（MVP 每条线索最多关联一条内容）
```

## 核心表

### inbox_items

`id PK, source_type, source_name, title, raw_text, summary, tags_json, extracted_json, status, original_filename, stored_filename, created_at, updated_at`。状态 PENDING/ORGANIZED/SAVED。附件放 `data/uploads/`，库中只存随机文件名。

### knowledge_entries

`id PK, title, content, summary, tags_json, source_inbox_id FK, source_type, source_ref, status, current_version, created_at, updated_at`。状态 ACTIVE。

### knowledge_versions

`id PK, knowledge_id FK, version_no, content, summary, change_reason, created_at`。`(knowledge_id,version_no)` 唯一；知识修改插入快照而不是覆盖历史。

### content_drafts

`id PK, topic, platform, audience, tone, title, body, source_knowledge_ids_json, status, generated_mode, created_at, updated_at`。平台键 xiaohongshu/douyin/x/wechat_official；状态 DRAFT/APPROVED/PUBLISHED；generated_mode 区分 ai 和 local_fallback。

### publish_records

`id PK, content_id FK, platform, publish_url, external_post_id, status, published_at, note, created_at`。当前只记录人工发布。

### leads

`id PK, name, company, contact, source_platform, source_content_id FK, requirement, budget, status, notes, created_at, updated_at`。

## 索引

- inbox_items(status, created_at DESC)
- knowledge_entries(updated_at DESC)
- content_drafts(status, created_at DESC)
- leads(status, created_at DESC)
