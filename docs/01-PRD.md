# 01｜产品需求文档（PRD）

版本：MVP 0.1。目标：个人开发者在有限投入下验证“信息→知识→内容→线索”的持续使用和付费价值。

## 用户画像

| 用户 | 核心问题 | 首版价值 |
|---|---|---|
| 个人创业者/销售 | 微信和资料分散，重要内容找不到 | 统一收集、摘要、待办和检索 |
| 自媒体创作者 | 内容断更，资料不能复用 | 从自有知识生成平台草稿 |
| 小微企业经营者 | 没有专职内容团队 | 用业务资料持续创作 |
| 代运营小团队 | 多客户、多账号协作 | 后续增加客户空间、审核和报表 |

## 用户故事

1. 我可以粘贴自己选定的微信文字或上传文件。
2. AI 生成摘要、标签和待办建议，但在我确认前不把资料自动认定为正式知识。
3. 我可以把信息沉淀为知识，保留来源和版本。
4. 我可以搜索知识、向知识库提问，并看到相关来源。
5. 我可以选择知识和主题，让 AI 分别生成多平台草稿。
6. 我可以编辑审核草稿，复制到平台发布并登记 URL。
7. 我可以记录咨询客户、来源平台、关联内容和跟进状态。
8. 我可以备份数据库和附件。

## 功能需求

### 工作台 P0

展示待处理信息、知识条目、待处理内容、开放线索数；最近收集和最近内容；快速入口；模型状态。新增资料后统计应更新。

### 信息收件箱 P0

支持文本粘贴，填写标题、来源类型、来源备注；上传 TXT/MD/CSV/JSON/PDF/DOCX，默认单文件 10 MB；保存原始文本；AI 提取摘要、标签、事实候选、待办候选和建议知识标题；用户主动沉淀。状态：PENDING、ORGANIZED、SAVED。拒绝不支持格式，扫描 PDF 不做 OCR。

### 桌面导入助手 P0

监控 `data/dropbox/`；仅处理用户主动保存的文件；成功导入后移动到 processed；失败保留原文件。提供文本剪藏命令行工具。

### 知识中心 P0

手工新建、从收件箱沉淀、关键词搜索、版本号和变更原因、知识问答。问答返回来源；未配置 AI 时明确标记为关键词检索，不伪装为模型回答。

### 内容中心 P0

输入主题、受众、语气，选择小红书/抖音/X/微信公众号和参考知识；每个平台独立生成草稿；可编辑、保存、审核、复制正文；审核后登记人工发布链接。当前不执行自动发布。

### 客户线索 P1

手工登记客户名称、公司、联系方式、来源平台、需求、预算、关联内容；状态 NEW、CONTACTED、QUALIFIED、WON、LOST。

### 设置 P0

展示模型配置状态、平台接入边界、桌面助手说明、数据目录和 API 文档。

## 非功能要求

- 默认仅监听 `127.0.0.1`，不得直接公网开放。
- 单文件上传 10 MB，提取文本默认上限 100,000 字符。
- 输入用 Pydantic 校验，SQL 参数化。
- SQLite 开启 WAL 和外键。
- 模型超时默认 60 秒；失败须明确 fallback。
- 原始资料和版本数据可备份。

## 关键流程

信息：`粘贴/上传 → PENDING → AI 整理 → ORGANIZED → 用户确认 → SAVED + 知识版本 1`。
知识更新：`编辑 → current_version + 1 → 插入 knowledge_versions`。
内容：`主题+知识 → DRAFT → 编辑 → APPROVED → 平台人工发布 → PUBLISHED_MANUALLY`。
线索：`咨询 → NEW → CONTACTED → QUALIFIED → WON/LOST`。

## MVP 实验指标

用 5–10 位种子用户验证：首次 15 分钟内能完成资料导入和知识沉淀；至少 60% 试用者完成一次知识到内容草稿闭环；第 2 周仍有 30% 以上试用者回来使用信息或内容模块；至少 3 人真实付费或提出可执行采购意向。以上是本项目实验目标，不是行业基准。
